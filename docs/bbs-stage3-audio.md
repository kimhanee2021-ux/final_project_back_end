# BBS 3단계: 저장된 대본의 음성 브리핑

선택한 공식 소식의 저장된 GPT 낭독 대본을 차분한 한국어 음성으로 읽는다. 요약 아래에서 **브리핑 듣기 → 일시정지 → 계속 듣기**, **정지 → 처음부터 다시 듣기**를 사용할 수 있다. 음성 준비 중에도 정지할 수 있다.

## 데이터와 API

- 추가 DB 변경 SQL은 없다. 기존 `games`, `game_news`, `game_news_briefings`를 수정하지 않는다. 기존 GPT 대본을 읽기만 한다.
- `POST /api/games/bbs/{appId}/news/{sourceId}/briefing/audio`
- 요청: `{ "sourceHash": "원문 SHA-256", "generatedAt": "현재 저장된 요약의 생성 시각" }`
- 응답: `audio/wav`, 24 kHz, 16-bit mono PCM, `Cache-Control: no-store`.
- 프론트에서 임의 대본이나 음성 모델을 받지 않는다. 기존 `BbsBriefingService.get`으로 게임·공식 원문·현재 GPT 버전을 확인하고, 화면의 생성 시각과 같은 저장 대본만 사용한다.
- 오래된 요약/변경된 원문은 409, 잘못된 요청은 400, 생성 중 중복 요청은 409, 호출 한도는 429, 미설정은 503, 생성 실패는 502다. 기존 공통 오류 형식의 한국어 메시지를 보여준다.

## OpenAI 연결

기존 백엔드 `OPENAI_API_KEY`를 사용한다. 브라우저로 키를 전달하지 않는다. 뉴스 요약과 STT 설정은 그대로 둔다.

```dotenv
BBS_BRIEFING_ENABLED=true
BBS_AUDIO_ENABLED=true
OPENAI_BBS_AUDIO_MODEL=gpt-realtime-2.1-mini
OPENAI_BBS_AUDIO_VOICE=marin
```

처음 설치하는 PC에서는 기존 3단계 요약용 SQL을 먼저 검토·적용해야 한다. 이미 적용한 DB에는 다시 실행하지 않는다. 음성을 추가하기 위한 SQL은 없다.

`OpenAiBbsSpeechClient`가 서버에서 Realtime WebSocket 세션 하나를 열어 저장된 대본만 전송한다. 차분한 한국어 낭독을 지시하며, 추가 설명·번역·새 사실·요약 없이 대본을 끝까지 읽도록 한다. 마이크 입력, VAD, 도구 호출, 대화 이력은 사용하지 않는다. 다른 AI 공급자로 전환하거나 자동 재시도하지 않는다.

완료 상태, 오디오 종료 이벤트, 길이/메시지 크기 제한과 출력 전사문을 검사한 뒤 WAV를 반환한다. 전사문 비교는 띄어쓰기·문장부호를 제외한 편집 거리를 사용해 큰 재작성이나 잘림을 거부한다. 발음의 정확성이나 모든 미세한 의미 변화를 보증하는 검사는 아니다. 실제 재생 길이는 브라우저의 음성 메타데이터로 표시한다.

기본 제한: 생성 요청 70초, 개별 이벤트 512 KiB, PCM 최대 90초(4,320,000 bytes), 출력 4,096 tokens. 저장 대본의 목표 분량은 기존 30~60초이며, 생성 시간이 길어지거나 불완전한 음성은 부분 재생하지 않는다.

공식 문서 확인 기준(2026-10-24): [Text to speech](https://developers.openai.com/api/docs/guides/text-to-speech), [Realtime conversations](https://developers.openai.com/api/docs/guides/realtime-conversations), [WebSockets](https://developers.openai.com/api/docs/guides/voice-websockets?voice-api=realtime). 현재 권장 Realtime 흐름을 사용하며 `/v1/audio/speech`에 Realtime 모델을 보내지 않는다.

## 재사용 및 재생 수명

- 서버 메모리에 최대 8개, 30분간 보관한다. 게임·소식·원문 해시·대본이 같을 때만 재사용한다. 서버 재시작 시 삭제된다. 모델/목소리 변경도 서버 재시작 후 적용된다.
- 같은 소식의 생성 요청은 한 번만 진행한다. 캐시가 없을 때만 별도 호출 한도(기본 일 100회, 주소별 분당 3회, 동시 2회)를 소비한다. 한도와 캐시는 서버 인스턴스별 메모리 상태다.
- 브라우저에서는 준비된 Blob을 일시정지·정지·재생에 재사용한다. 소식 전환, 화면 이탈 시 요청 취소, 재생 중지, 오디오 연결 해제, Blob URL 회수를 수행한다. 늦은 응답이 다른 소식에서 재생되지 않는다.
- 음성 준비 중 정지하면 브라우저 요청은 취소된다. 서버에서 이미 시작한 생성은 최대 제한 시간까지 완료되어 캐시에 남을 수 있다. 완료된 음성이 자동으로 재생되지는 않는다.
- 마이크 시작은 브리핑을 정지한다. 브리핑 시작은 마이크 인식을 취소한다. Esc와 탭 숨김도 브리핑을 정지한다.
- 자동 재생이 브라우저에서 차단되면 준비된 음성을 유지하고 다시 누르도록 안내한다. 재시도 클릭으로 음성을 다시 생성하지 않는다.
- 화면에 `AI가 만든 음성`을 표시한다. 음성 오류가 발생해도 요약과 원문을 계속 읽을 수 있다.

## 검증

- 백엔드: 신규 클라이언트/서비스 12개 테스트. WebSocket 메시지 분할·오류·시간 초과·크기 제한·불완전 음성, 저장 버전 검증, 캐시 만료/상한, 중복 생성 방지, 실패 시 호출 한도를 확인했다. 기존 뉴스·검색·게시판을 포함한 선택 테스트 총 133개와 빌드도 통과했다.
- 프론트: 신규 재생 수명 테스트 7개와 기존 요약·뉴스·녹음 13개, ESLint 및 빌드 통과.
- 실제 CS2 저장 대본 1개로 OpenAI 음성 생성: **41.75초**, WAV 2,004,044 bytes. 첫 생성 약 7.8초, 캐시 응답 약 19ms. 같은 요청의 음성 bytes가 일치했다.
- 브라우저 12개 시나리오: 실제 음성 재생/정지/일시정지/이어서 듣기, 소식 변경, 생성 중 취소 및 늦은 응답, 마이크 상호 정지, 자연 종료, Esc, 탭 숨김 이벤트, 공급자 오류, 자동 재생 거부, 모바일 390px/320px 및 앱 내 다른 화면으로 이동. 오류/지연 사례는 유료 호출 없이 응답을 대체했다.
- 실제 DB 연결을 읽기 전용으로 두고 모든 시드·수집 작업을 끈 별도 미리보기에서 검증했다. 기존 15개 뉴스, 15개 이전 요약의 모든 기존 컬럼과 게임 수/범위가 백업과 일치했다.

프론트/백엔드 모두 기존 `BBS04`에서 변경했으며 push/merge는 하지 않았다. 배포 환경의 HTTPS, 사용자별 사용량 정책, 음성 명령으로 소식을 선택하는 다음 단계는 별도 범위다.
