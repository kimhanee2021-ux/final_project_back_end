# BBS04 3-1: 한국어 요약·낭독 대본 생성과 저장

## 제공 범위

선택한 Steam 공식 소식 **1개**에 대해 한국어 제목, 서로 다른 핵심 요약 **3개**, 차분한 **30~60초 목표**의 낭독 대본을 만든다. 상세 화면의 `한국어 요약 만들기` 버튼으로만 생성한다. 페이지 조회/새로고침은 저장 결과 조회만 수행하며 AI 호출을 시작하지 않는다. 공식 소식·패치·이벤트·개발 소식 분류와 외부 기사 제외 규칙은 그대로다.

TTS 생성/재생과 음성 명령 해석은 이 단계에 포함하지 않는다. 0.2초 음성 검색 시작, 0.5초 취소, 녹음 중에만 안내 표시 동작도 유지한다.

## API와 생성 규칙

- `GET /api/games/bbs/{appId}/news/{sourceId}/briefing?sourceHash=...`: 저장 결과만 조회. 상태는 `EMPTY`, `READY`, `STALE`, `PROCESSING`, `UNAVAILABLE`이다. `sourceId`는 Steam gid **문자열**이다.
- `POST` 같은 경로, 본문 `{ "sourceHash": "..." }`: 선택한 소식의 생성 요청. 원문이나 프롬프트는 프론트에서 받지 않는다.
- 공식 뉴스 응답에 `sourceHash`가 추가된다. 서버가 현재 뉴스 목록의 appId/gid/해시를 다시 검증한다. 원문이 바뀌었으면 409, 목록에 없으면 404다. 현재 뉴스 범위는 기존과 같이 최신 최대 40개다.
- 결과는 제목, 정확히 3개인 한국어 요약, 한국어 대본을 검사한 후 저장한다. 원문 80자 미만/24,000자 초과는 생성하지 않으며 긴 본문을 잘라 전체 요약인 것처럼 제공하지 않는다. 모델도 근거가 부족하면 생성 불가를 반환하도록 한다.
- 대본은 공백 포함 240~520자다. 화면의 초 수는 길이에 따른 **추정치**이며 실제 음성 길이는 TTS 단계에서 검증한다. 근거 충실도·한국어 자연스러움은 실제 모델 응답 검토가 필요하며 형식 검증이 사실 정확성을 보장하지 않는다.
- OpenAI Responses API, Structured Outputs를 사용한다. 기본 모델 `gpt-5.4-mini`, `store=false`, 원문은 지시문과 분리한 JSON 데이터다. 다른 AI 제공자로 전환하지 않는다.
- 제공자 요청은 45초/응답 128KiB/출력 2,400토큰으로 제한한다. 자동 재시도 없음. 원문, 키, 제공자 오류 본문을 로그에 기록하지 않는다.
- 기존 공개 `/api/games/**` 정책을 따른다. 생성 한도는 서버 인스턴스별 일 100회, 주소별 분 3회, 동시 2회다. `app.bbs.briefing.daily-calls`, `calls-per-minute`, `concurrent-calls`로 변경 가능하다. 메모리 집계이며 재시작/여러 서버 공통 비용 한도는 아니다. 실패 호출도 계산한다.

## 기존 데이터 보존과 DB 변경

현재 저장소에 뉴스 저장 Entity/Repository가 없어, `domain/gamenews/repository/BbsBriefingRepository`에서 기존 두 테이블에 대한 쓰기 컬럼을 명시한다. 기존 `Game`/Repository는 재사용하며 중복 게임 Entity나 cascade를 추가하지 않는다.

- `games`, `game_search_names`, 기존 뉴스/브리핑 값은 변경하지 않는다.
- `game_news`에 같은 `(app_id, source_news_id)`가 있으면 원문을 덮어쓰지 않는다. 없는 기사만 새 행을 삽입한다.
- `game_news_briefings`의 기존 Gemini `summary`, `ai_content`, 상태, 모델, 오류 기록은 변경하지 않는다. 없는 행은 기존 필수 컬럼을 `PENDING`/재시도 0으로 초기화한다. 이 레거시 상태는 GPT 완료 상태가 아니며 기존 자동 생성기는 이 브랜치에서 실행하지 않는다.
- GPT 결과와 실제 생성에 사용한 최신 원문 스냅샷은 새 `gpt_payload`에 JSON 문자열로 함께 저장한다. 원문 해시·모델·프롬프트 버전·생성 시각을 별도로 기록한다. 원문/모델/프롬프트가 같으면 저장 결과를 재사용한다. 달라지면 `STALE`로 표시하고 명시적 요청으로 GPT 컬럼만 갱신한다.
- 생성 요청은 DB 시각 기준 90초 lease를 획득한다. 소유 토큰을 확인해 저장/해제하므로 여러 서버의 같은 기사 요청도 중복 생성을 막는다. 만료된 소유자는 최신 결과를 덮어쓸 수 없다. 외부 API를 기다리는 동안 DB 트랜잭션을 열어두지 않는다.
- 생성 실패 시 기존 성공 결과를 지우지 않는다. 화면을 떠나면 프론트의 응답 반영은 취소되지만, 이미 시작한 서버 생성은 완료 후 저장될 수 있다. 돌아오면 GET으로 확인한다.

검토할 SQL: [bbs-gpt-briefing-additive.sql](db/bbs-gpt-briefing-additive.sql). 기존 `game_news_briefings`에 nullable 컬럼 **7개**만 추가한다. `DROP`, `DELETE`, 기존 컬럼 변경, 게임 재적재는 없다. 현재 로컬 DB에는 사용자에게 SQL을 먼저 제시하고 임시 테이블 검증과 백업을 마친 후 적용했다. 다른 팀원 DB에는 자동으로 적용되지 않는다.

## 활성화 순서

1. 대상 DB와 기존 두 뉴스 테이블의 컬럼·PK/외래키·`uq_game_news_source`를 대조한다. 빈 팀원 DB는 팀의 기존 뉴스 스키마부터 준비한다. 검색용 `bbs-local-demo.sql`만으로는 요약 저장 테이블이 준비되지 않는다.
2. 추가 SQL을 사용자에게 보여주고 적용을 확인한다. MySQL DDL은 암묵적으로 커밋되므로 검토한 백업/배포 시간에 **한 번만** 실행한다. 이미 컬럼이 있으면 ALTER를 재실행하지 않고 정의를 대조한다.
3. 백엔드 `.env` 또는 서버 환경에 `BBS_BRIEFING_ENABLED=true`, `OPENAI_BBS_SUMMARY_MODEL=gpt-5.4-mini`, `OPENAI_API_KEY`를 설정하고 재시작한다. 실제 키는 Git에 올리지 않는다.
4. 공식 소식 1개를 선택해 생성·저장·새로고침 후 재사용을 확인한다. 모델 접근 권한과 API 사용 한도가 필요하다.

기본값 `BBS_BRIEFING_ENABLED=false`에서는 새 컬럼 조회나 쓰기, GPT 호출을 수행하지 않는다. `ddl-auto=none`/`sql.init.mode=never`도 유지한다. 따라서 SQL 적용 전에도 기존 앱을 실행할 수 있다. 현재 작업 PC의 `.env`는 검증 후 `BBS_BRIEFING_ENABLED=true`로 설정했으며 백엔드 재시작부터 적용된다. 음성 재생 연결은 다음 단계에서 별도 확인 후 진행한다.

## 검증

- H2 MySQL 모드의 독립 DB: 저장/재조회, 세 가지 요약 검증, 기존 행·Gemini 값 보존, 원문 변경, 불완전 응답, 실패 시 성공본 보존, 동시 요청·lease 만료/소유권, 모델 변경/키 없음 동작.
- 로컬 가짜 OpenAI 서버: 요청 형식, 비밀키/모델 검증, 응답 제한, 잘못된 JSON/거부/중단/부족한 본문, 오류/시간 제한. 유료 OpenAI 호출은 수행하지 않는다.
- 실제 MySQL: 세션에만 존재하는 임시 테이블에서 제공 SQL을 그대로 적용해 문법과 기존 값 보존을 먼저 검증한다. 이후 검토한 추가 SQL만 실제 테이블에 적용하고 백업한 기존 컬럼 값을 대조한다.
- 브라우저: 실제 뉴스 조회 및 비활성 상태 확인. 생성/저장 표시 화면은 제어된 응답으로 PC·모바일·다크 모드, 기사 전환, 새로고침, 중복 클릭, 저장소/제공자 오류를 검증한다. 이 화면 테스트는 실제 GPT 응답 품질/저장 검증과 구분한다.

공식 API 근거: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini).

### 검증 결과 — 2026-10-24

- 게임·게시판·뉴스 회귀 117개 통과. 이후 비활성/DB 오류/호출 제한/키 없는 캐시 검증 4개를 추가했으며 새 기능 테스트 18개가 통과했다. 프론트 모델·뉴스·녹음 테스트 13개, ESLint, 두 빌드 통과. 기존 프론트 500kB 번들 경고는 남아 있다.
- 제어된 브라우저 검증 10개 통과. 실제 GPT 저장 결과에 대해서도 PC·모바일·새로고침 표시를 확인했다.
- 실제 OpenAI `gpt-5.4-mini`로 CS2 소식 **1개**를 생성했다. 첫 결과에서 UTC와 한국 날짜 차이를 발견해 프롬프트를 `bbs-ko-2`로 보완하고 같은 소식을 한 번 재생성했다. 유료 생성 총 **2회**, 저장된 GPT 소식은 **1개**다. 한국 시간 게시일, 핵심 3개, 약 43초로 추정한 대본을 확인했다.
- 원문을 직접 대조해 프리캐시/인질 API, Console·GameRules, 레이더·로그 개선 내용이 실제 공지에 포함됨을 확인했다. 실제 낭독 길이와 발음은 아직 검증하지 않았다.
- 반복 생성 요청과 GET 재조회는 저장본을 재사용했다. 임시 서버의 생성 한도 1회 내에서 반복 POST가 성공해 추가 유료 호출이 없음을 확인했다.
- 게임 69,919개, 뉴스 15개 및 브리핑 15개 유지. 기존 뉴스 및 Gemini 브리핑의 **모든 기존 컬럼 값**이 백업과 일치한다. 검증한 CS2 소식은 이미 저장된 행이어서 행을 추가하지 않았고, 해당 행의 새 GPT 컬럼에만 생성 결과를 저장했다. 적용 전 백업은 작업 폴더 `bbs04-stage3-summary/audit/pre-migration-backup`에 보관했다.
- 프론트/백엔드 BBS04 유지. commit/push/merge 및 음성 재생 연결은 수행하지 않았다.
