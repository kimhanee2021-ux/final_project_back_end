# 공지사항 API

## 범위

제목·내용·작성일을 갖는 공지사항의 목록, 상세, 작성, 수정, 삭제 및 페이지 나누기.
커뮤니티 게시판과 별도의 `notices` 테이블을 사용한다.
검색, 중요 공지 고정, 댓글, 추천, 이미지 첨부는 이번 기본 범위에 포함하지 않는다.

## 인증 및 권한

기존 보안 설정에 따라 모든 API는 `Authorization: Bearer <JWT>`가 필요하다.
관리자 역할이 아직 없으므로 현재는 로그인한 회원이 작성하고 작성자만 수정·삭제한다.
**관리자 전용 공지사항으로 운영하려면 팀의 관리자 체계 확정 후 작성·수정·삭제 권한을 연결해야 한다.**
읽기 공개 여부도 기존 `/api/**` 로그인 정책을 따른다.

## API

| 메서드 | 경로 | 응답 |
|---|---|---|
| GET | `/api/notices?page=0&size=20` | 200, 최신순 목록 |
| GET | `/api/notices/{id}` | 200, 상세 |
| POST | `/api/notices` | 201, 상세와 Location 헤더 |
| PUT | `/api/notices/{id}` | 200, 수정된 상세 |
| DELETE | `/api/notices/{id}` | 204 |

작성 및 수정 요청:

```json
{"title":"서비스 점검 안내","content":"오늘 점검합니다."}
```

제목: 필수, 공백만 입력 불가, 최대 255자. 내용: 필수, 공백만 입력 불가, 최대 10000자.
작성자 ID와 작성일은 서버에서 설정하며 요청으로 변경할 수 없다.
작성일은 생성 후 유지하며 수정 시 `updatedAt`을 설정한다.
작성자가 탈퇴해도 공지는 유지하고 작성자 연결만 해제한다(`authorId: null`).
작성자가 없는 공지는 일반 회원이 수정·삭제할 수 없다. 관리 처리 정책은 관리자 체계 연결 시 확정한다.

목록:

```json
{
  "content":[{"id":1,"title":"서비스 점검 안내","createdAt":"2026-10-10T14:00:00"}],
  "page":0,"size":20,"totalElements":1,"totalPages":1,"first":true,"last":true
}
```

`page`는 0부터 시작, `size`는 1~100. 작성일 내림차순, 같은 작성일은 ID 내림차순.
목록에는 본문을 포함하지 않는다. 상세는 id/title/content/authorId/createdAt/updatedAt을 반환한다.

오류: 400 입력값/페이지 오류, 401 로그인 필요, 403 다른 작성자의 수정·삭제, 404 없는 공지.
본문 검증 오류는 기존 게시판과 같은 `{error, errors}` 구조를 사용한다.

## DB 적용

`docs/sql/notices.sql`은 테이블 추가용 SQL이다. 실제 MySQL에는 아직 실행하지 않았다.
기존 `users.id`의 타입과 부호가 `BIGINT`와 일치하는지 확인한 뒤 팀의 DB 적용 방식으로 실행한다.
자동 테스트는 실제 운영 DB가 아닌 H2에서 실행했다.

## 개발 상태

로컬 작업 사본의 `codex/notice-api` 브랜치. GitHub 업로드 및 병합은 하지 않았다.
기존 로컬 게시판 커밋 `dfbbc0b`를 기반으로 작업했으므로 팀 최신 브랜치와 통합할 때 최신 변경을 확인한다.
프런트 화면은 이번 백엔드 범위에 포함하지 않는다.
