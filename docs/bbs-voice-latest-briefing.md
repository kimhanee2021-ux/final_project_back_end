# 음성 요청으로 최신 공식 소식 1개 브리핑

## 동작

원형을 0.2초 누르고 **“카운터스트라이크 2 최신 소식 들려줘”**라고 말하면 다음 순서로 진행한다.

1. 기존 OpenAI STT로 전체 요청을 텍스트로 변환한다.
2. GPT가 게임 검색(`SEARCH`)과 최신 공식 소식 낭독(`LATEST_BRIEFING`)을 구분한다.
3. 기존 `games`와 활성 `game_search_names`에서 게임을 확인한다. 게임이 여러 개일 수 있으면 검색 목록에서 선택을 받는다.
4. 기존 Steam 공식 소식 API에서 게시 시각이 가장 최근인 소식 **1개**를 선택한다. 분류/페이지 필터는 초기화한다.
5. 원문 해시와 일치하는 GPT 요약이 있으면 재사용한다. 없거나 오래됐으면 기존 요약 API로 핵심 3가지와 낭독 대본을 한 번 생성·저장한다.
6. 기존 음성 플레이어로 넘겨 차분한 음성 재생을 시작한다. 브라우저가 자동 재생을 막으면 이미 준비한 음성을 `브리핑 듣기` 버튼으로 재생한다.

게임 이름만 말하거나 “스타듀 밸리 찾아줘”라고 하면 검색 결과만 보여준다. “뉴스 읽지 마”, 여러 게임 동시 요청, 특정 과거 날짜/분류의 소식 등 이번 범위 밖 요청은 자동 브리핑을 시작하지 않는다. 게임 이름이 없으면 게임 이름을 함께 말하도록 안내한다.

## 기존 데이터와 코드 활용

이번 단계에 추가 DB 변경 SQL이나 Entity는 없다. 게임명/별칭 조회는 기존 `GameRepository`와 `BbsGameSearchService`를 확장했다. 게임 원본 데이터와 기존 뉴스·이전 AI 요약을 삭제하거나 덮어쓰지 않는다. 새 요약을 만들 때는 앞 단계의 `BbsBriefingService`와 기존 GPT 전용 컬럼 저장 규칙을 그대로 사용한다.

`POST /api/games/bbs/voice/commands`에 `{ "transcript": "인식한 요청" }`를 보낸다. 응답은 `status`, `action`, `query`, `game`, `candidates`, `hasMore`다. 상태는 `SEARCH`, `RESOLVED`, `CHOOSE_GAME`, `NOT_FOUND`, `NEEDS_GAME`, `UNSUPPORTED` 중 하나다.

이 API는 GPT 요청 해석과 게임 조회까지만 담당한다. 소식 조회·요약·음성 API는 프론트의 취소 가능한 `VoiceBriefingFlow`가 순서대로 호출한다. 모델이 App ID나 실행할 API를 지정하지 못하며, 임의 도구 실행이나 웹 검색도 하지 않는다.

GPT 연결은 기존 백엔드의 `OPENAI_API_KEY`와 새 선택 설정 `OPENAI_BBS_COMMAND_MODEL=gpt-5.4-mini`를 사용한다. Responses API의 strict JSON schema, `store:false`, 최대 출력 700 tokens, 응답 16 KiB, 20초 제한을 적용한다. 기본 요청 한도는 서버 인스턴스별 일 100회, 주소별 분당 6회, 동시 2회다. API 키와 원문 음성/요청을 새 DB 테이블이나 애플리케이션 로그에 저장하지 않는다. 다른 AI 공급자나 자동 재시도로 전환하지 않는다.

공식 구현 기준: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). 생성 모델이 정해진 결과 구조를 반환하도록 하고 서버에서도 결과를 검증한다.

## 모호성, 최신성, 취소

- STT가 버전 번호를 놓칠 수 있으므로 인식한 문장을 화면에 표시한다. 예를 들어 숫자 없는 `Counter-Strike`는 구버전의 정확한 이름이기도 하다. 번호가 없는 이름으로 여러 게임이 검색되면 정확히 일치하는 구버전이 있어도 선택을 받는다. 숫자를 명시한 제목/별칭이 정확히 한 게임과 일치하면 자동으로 선택한다. 정확한 이름 일치가 없어도 검색 결과가 하나뿐이고 추가 결과가 없으면 해당 게임을 사용한다.
- Steam의 기존 공식 소식 캐시(최대 5분)를 사용한다. 게시 시각으로 정렬하고 원문 해시를 확인한다. 서버가 이전 스냅샷(`stale`)만 제공하거나 소식이 없으면 중단하며, 과거 소식을 최신이라고 읽지 않는다.
- 요약이 다른 요청에서 생성 중이면 최대 60초 동안 GET으로만 결과를 확인한다. 유료 생성 POST를 반복하지 않는다. 실패/본문 부족이면 안내하고 원문은 계속 볼 수 있다.
- 새 음성 입력, 수동 검색, 게임/소식/분류/페이지 변경, 뒤로 가기, Esc, 탭 숨김, 화면 이탈은 진행 중 요청을 취소한다. 이미 서버에서 시작한 요약 생성은 앞 단계 규칙대로 저장을 완료할 수 있지만, 취소된 요청의 늦은 결과는 재생되지 않는다.
- 재생 요청은 URL에 저장하지 않는다. 새로고침·뒤로 가기·React StrictMode 재설정으로 요약 생성이나 음성이 다시 자동 실행되지 않는다. 페이지 내부의 연속적인 게임→소식 이동은 같은 요청으로 유지한다.
- 기존 일시정지·계속 듣기·정지, 다른 소식 선택 시 음성 정지, 마이크와 재생의 상호 정지는 그대로 동작한다.

## 검증 기록 — 2026-10-25

- 신규 백엔드 요청 해석/DB 통합 테스트 12개. strict 응답·거부·실패·시간/크기 제한, 제목/한국어 별칭, 중복 별칭·시리즈 이름 모호성, 비활성 별칭, 입력 검증, 기존 게임 데이터 보존, 호출 한도 확인.
- 신규 프론트 흐름 테스트 10개. 최신 소식 한 개, 저장된 요약 재사용, 후보 선택 대기, 소식 없음/오래된 스냅샷, 단계별 취소, 연속 이동/뒤로 가기, 생성 중 GET 확인, 오류와 중복 재생 방지 확인. 기존 녹음·뉴스·요약·플레이어 테스트와 빌드도 통과.
- 최종 선택 회귀 테스트 합계: 백엔드 **145개**, 프론트 **30개**, 실패 0개. 프론트 ESLint와 양쪽 빌드도 통과했다.
- 브라우저 모의 응답 시나리오 8개: 새 요약→음성 한 번, 모호한 게임 선택 후 재개, 일반 검색/지원 범위, 소식·요약 실패, 명령 해석 취소, 요약 도중 다른 소식 선택, 자동 재생 차단 후 재사용, 모바일 390px/320px·Esc. 유료 API 호출 없이 검증.
- 실제 연결 시나리오 3개: 로컬에서 합성한 한국어 시험 음성을 브라우저의 실제 MediaRecorder로 녹음하여 OpenAI STT→GPT 요청 해석→DB의 CS2(App ID 730)→Steam 최신 소식→저장된 GPT 요약→OpenAI 음성 **44.1초** 재생까지 확인. STT/요청 해석/음성 생성은 각각 한 번, 요약 생성은 캐시 재사용으로 0회였다. 일시정지·계속 듣기·소식 전환 시 정지도 확인했다. 실제 사용자 마이크/주변 소음에 대한 정확도 평가를 뜻하지 않는다.
- 실제 GPT로 일반 게임 검색, 낭독 거부, 게임명 없는 요청도 확인했다. 첫 합성 음성에서 숫자 2가 누락된 사례를 발견해 시리즈 이름 모호성 처리와 버전 보존 지침을 보완했고, `투`로 또렷이 발음한 입력은 `카운터 스트라이크 2 최신 소식 들려줘.`로 인식됐다.
- 숫자가 누락됐던 전사문을 보완 후 실제 GPT에 다시 전달해 `CHOOSE_GAME`과 후보 3개를 반환하는 것을 확인했다. 구버전으로 자동 진행하지 않았다.
- 실제 DB 검증은 읽기 전용 연결, 자동 DDL/시드/수집 비활성 상태에서 수행했다. 새 DB 마이그레이션을 실행하지 않았다.
- 기존 15개 뉴스·15개 이전 요약의 기존 컬럼과 게임 수/범위가 앞 단계 백업과 일치했다.

브랜치는 프론트·백엔드 모두 `BBS04`다. commit/push/merge는 하지 않았다. 추가 기능은 사용자 의견을 받은 다음 단계에서 진행한다.
