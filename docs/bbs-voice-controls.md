# BBS04 음성 제어와 실시간 입력

2026-10-25. 기존 `games`, `game_search_names`, `game_news`, `game_news_briefings`와 저장 데이터는 그대로 사용한다. 이 단계의 DB 변경 SQL은 없다.

## 사용자 동작

- 원형을 0.2초 누르면 마이크가 켜진다. 브리핑 재생 중이면 즉시 일시정지하여 음성이 마이크로 다시 들어가지 않도록 한다.
- 안내문 바로 위 `지금 하시는 말씀`에 인식 중인 문장을 표시한다. 중간 문장은 명령을 실행하지 않는다. 말이 끝나고 2초간 조용하면 확정 문장 하나를 처리한다.
- `멈춰`: 현재 브리핑을 일시정지하고 위치를 유지한다. `계속 읽어줘`: 같은 음성을 그 위치부터 이어 듣는다. 요약·음성을 다시 생성하지 않는다.
- `다음 소식 들려줘`: 현재 선택한 게임·글을 기준으로, 최신순 공식 목록의 바로 다음 글을 선택한다. 공식 소식·패치·이벤트·개발 소식을 포함하며 외부 기사는 제외한다. 필터는 전체로 바꾸고 해당 글이 있는 목록 페이지로 이동한다.
- 다음 글을 선택하기 전에 이전 음성을 정지하고, 저장된 요약을 재사용하거나 기존 생성 API로 요약 3개와 대본을 만든 뒤 브리핑으로 연결한다. 마지막 글에서는 순환하지 않는다. 현재 글이 목록에서 사라졌거나 목록이 오래된 상태라면 안내한다.
- 다시 0.5초 누르거나 Esc를 누르면 음성 입력을 취소하고 자막을 숨긴다. 마이크를 켜며 일시정지한 브리핑의 위치는 유지한다. 게임·글을 수동 변경하거나 페이지를 떠나면 기존 음성을 해제한다.
- 진행 안내의 `닫기`는 재생 위치를 지우지 않는다. `요청 취소`는 진행 중인 자동 작업을 취소한다. 재생 영역의 `정지` 버튼은 기존처럼 처음으로 되돌린다.

## 연결

브라우저 AudioWorklet → 같은 출처의 `/api/games/bbs/voice/live` WebSocket → 서버 OpenAI transcription session → 중간/확정 문장 → 기존 `/voice/commands` → 재생 제어 또는 기존 뉴스·요약·음성 API.

OpenAI 공식 문서: https://developers.openai.com/api/docs/guides/realtime-transcription

- 실시간 입력은 `gpt-live-transcribe`, 명령 해석은 기존 `gpt-5.4-mini`를 사용한다. 한국어 요약과 음성 생성 설정은 기존 값을 사용한다. 다른 제공자나 브라우저 SpeechRecognition으로 전환하지 않는다.
- 서버 `.env`: 기존 `OPENAI_API_KEY`, 새 `OPENAI_LIVE_STT_MODEL=gpt-live-transcribe`(기본값). 일반 API 키를 브라우저로 보내지 않는다. 스트리밍 모델은 실제 중간 문장을 지원하는 이 모델로 제한한다.
- 명령 enum에 `NEXT_BRIEFING`, `PAUSE`, `RESUME`를 추가한다. 응답은 `status: CONTROL`, 빈 query/candidates, game null이다. GPT가 게임 ID나 다음 글을 추측하지 않는다.
- 기존 파일 업로드 STT API는 호환성을 위해 남아 있으나 BBS 원형 입력은 새 실시간 연결을 사용한다.

## 실행 환경과 제한

- 최신 Chrome/Edge, localhost 또는 HTTPS, 마이크 권한이 필요하다. 음성 명령도 원형을 눌러 입력하며 상시 녹음하지 않는다.
- 개발 서버는 기존 `AI_API_TARGET`으로 `/api`와 WebSocket을 함께 전달한다. 운영 환경도 동일 출처 `/api/games/bbs/voice/live`의 Upgrade 연결을 백엔드로 전달해야 한다. 별도 출처의 직접 연결은 허용하지 않는다.
- 단일 발화, mono PCM16 24kHz, 프레임 100ms, 최대 30초/1,440,000바이트. 무음 10초 종료, 말 뒤 무음 2초 확정, 연결 12초/확정 대기 15초, 서버 전체 수명 55초 제한이다.
- 서버는 기존 STT의 일일/IP별/동시 호출 제한을 공유한다. 취소·오류·연결 종료 시 서버 세션과 마이크를 해제한다. 녹음과 인식 문장은 DB나 파일에 저장하지 않는다. 제한은 서버 인스턴스별 메모리 기준이다.
- 브라우저의 자동 재생 제한에 걸리면 `브리핑 듣기`를 직접 눌러야 한다. 준비된 음성을 재사용한다.

## 검증

- 백엔드 152개, 프론트 40개 자동 테스트 통과. 프론트 lint/build 통과. 기존 대형 번들 경고는 남아 있다.
- 실제 OpenAI 실시간 STT·GPT 명령 해석에 한국어 샘플 음성을 전달하여 `멈춰`, `계속 읽어줘`, `다음 소식 들려줘`와 말이 끝나기 전 중간 문장 도착을 확인했다. 브라우저의 실제 AudioWorklet과 Audio 재생을 사용했다. TTS는 이전에 검증된 WAV를 재사용했고 다음 글/요약은 테스트 응답으로 대체하여 운영 DB 쓰기와 불필요한 음성 생성을 피했다.
- 별도 브라우저 검증으로 신규 요약 → 다음 글 재생 1회, 이전 음성 해제, 마지막 글 안내, 진행 중 글 변경·취소, 390/320px 및 밝은/어두운 화면을 확인했다. 기존 검색·게임 선택·요약 실패·자동 재생 제한 시나리오도 재검증했다.
- 기존 “카운터스트라이크 2 최신 소식 들려줘”도 새 실시간 STT로 검증했다. 실제 GPT 명령 해석 → 기존 DB의 app_id 730 → 실제 Steam 최신 공식 소식 → 저장된 한국어 요약 → 브라우저 재생으로 이어졌다.
- 실제 사람의 마이크/소음 환경은 별도 사용 확인이 필요하다. 이 테스트는 생성한 한국어 샘플 음성을 마이크 스트림에 공급했다.
- 실제 DB는 읽기 전용으로 점검했다. 기존 게임 수·ID 범위, 기존 뉴스 15행과 기존 브리핑 15행, 저장된 GPT 요약을 보존했다.
