# BBS 2단계: Steam 공식 뉴스

## 동작

- 프론트 `/bbs`에서 기존 게임 검색 → 게임 선택 → 공식 소식 목록/상세로 연결한다.
- `GET /api/games/bbs/{appId}/news`는 기존 `BbsGameSearchService`로 게임 존재 여부를 확인하고 최신 공식 소식 최대 40개를 반환한다.
- Steam `ISteamNews/GetNewsForApp/v2`에 `maxlength=0`, `feeds=steam_community_announcements`를 전달한다. 응답도 같은 feed와 `feed_type=1`인지 검사한다. 외부 매체 기사는 제외한다.
- **`is_external_url`로 공식/외부 매체를 구분하지 않는다.** Steam 공식 리디렉션도 이 값이 true다. 원문 링크는 검증한 Steam 호스트의 HTTPS 주소만 허용한다.
- gid는 문자열, 시각은 UTC ISO-8601로 전달한다. 프론트는 한국 시간으로 표시한다.
- 원문은 HTML/BBCode를 실행하지 않는 일반 텍스트로 표시한다. 이미지/영상 중심 소식은 공식 원문 링크에서 확인한다.

## 분류 및 범위

패치 태그 우선 → 개발 관련 제목 → 패치 관련 제목 → 이벤트 관련 제목 → 나머지는 공식 소식 순서다. 이 네 그룹은 GameSense 표시 규칙이며 Steam이 제공하는 정확한 이벤트 유형이 아니다. 제목만으로 구분하기 어려운 소식은 공식 소식에 남는다.

목록의 네 분류 필터와 페이지는 현재 가져온 최대 40개에 적용한다. 전체 과거 기사 검색이 아니다. 게임·분류·페이지·선택 소식은 URL로 복원한다. 한국어 제목/요약/낭독과 음성 생성은 다음 단계에서 별도로 진행한다.

## 기존 데이터 보존과 부하 제한

이번 단계는 **DB 읽기만 수행**한다. Game Entity/게임 데이터/기존 뉴스 테이블을 수정하지 않으며 새 Entity나 마이그레이션도 없다. ZIP의 SteamNewsClient, SteamNewsItem, GameNewsCategory, 예외 및 관련 테스트 중 필요한 부분만 가져와 보완했다.

뉴스는 서버 메모리에 게임별 5분, 최대 32개 게임까지 보관한다. 동시 Steam 요청은 최대 4개이며 동일 게임 요청을 합친다. 연결 제한 3초/요청 제한 8초, 실패 재시도 간격 30초다. 실패 시 1시간 이내 이전 성공본만 stale 표시와 함께 반환한다. 성공 이력이 없거나 오래되면 503을 반환한다. 앱 재시작 시 이 메모리 보관분은 사라진다.

실제 DB에는 DDL/DML을 실행하지 않는다. 자동 수집이나 유료 AI/TTS 호출도 없다. 다음 단계에서 영구 저장이 필요하면 이미 존재하는 `game_news` 계층과 스키마를 먼저 대조해 재사용한다.

## 검증

게임/게시판 회귀 테스트와 `domain.gamenews` 테스트는 H2 메모리 DB로 실행한다. 프론트는 ESLint, 빌드, `node --test tests/bbsNews.test.js`와 실제 Steam 응답을 이용한 PC/모바일 브라우저 점검으로 검증한다. 실제 DB 확인은 읽기 전용 연결을 사용한다.

API 근거: [Valve ISteamNews 문서](https://partner.steamgames.com/doc/webapi/ISteamNews).
